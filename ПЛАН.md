# Что доделать, чтобы CRM заменила BigBird

Сейчас в системе уже есть: товары с папками, контрагенты, склад (приёмка), заявки с позициями и печатью (счёт, ПКО), накладные и касса, аналитика, несколько «баз» (рабочих пространств), импорт из 1С, юрлица в одной базе.

Ниже — этапы. Делаем сверху вниз.

## Этап 1. Документы (ГОТОВО) должны создаваться и правиться руками
- [x] Накладная: создание с нуля (продажа и закупка), редактирование позиций, удаление, печать ТОРГ-12 и УПД.
- [x] Касса: создание ПКО и РКО вручную, привязка к контрагенту и статье движения денег, печать КО-1/КО-2.
- [x] Возврат от покупателя и возврат поставщику как отдельные виды документов.
- [x] Копирование любого документа («создать на основании»).

## Этап 2. Живые остатки (ГОТОВО) и себестоимость
- [x] Накладная при проведении сама двигает склад: продажа списывает, закупка приходует.
- [x] Статус «проведён / черновик», отмена проведения возвращает остатки.
- [x] Себестоимость по партиям (FIFO) и прибыль по каждой продаже.
- [x] Запрет продавать в минус (настраиваемо) и предупреждение при нехватке.

## Этап 3. Деньги и долги (ГОТОВО)
- [x] Оплаты привязываются к заявкам и накладным, видно «оплачено / осталось».
- [x] Карточка контрагента: сальдо, история документов, долг.
- [x] Отчёт по задолженности и по движению денег (приход/расход по статьям).

## Этап 4. Работа командой (ГОТОВО)
- [x] Приглашение сотрудников в базу по e-mail.
- [x] Роли: владелец, менеджер, кладовщик, наблюдатель.
- [x] История изменений документа (кто и когда менял).

## Этап 5. Ежедневное удобство (ГОТОВО)
- [x] Общий поиск по всей системе (товар, контрагент, номер документа).
- [x] Фильтры в списках с запоминанием, постраничная загрузка больших списков.
- [x] Выгрузка любого списка в Excel, печать в PDF.
- [x] Работа с телефона и планшета.
- [x] Массовые действия: смена цены, перенос товаров между папками, удаление группой.

## Этап 6. Отчёты как в BigBird (ГОТОВО)
- [x] Продажи по периодам, по товарам, по контрагентам.
- [x] Продажи по менеджерам (кто создал документ).
- [x] Оборотная ведомость по складу за период.
- [x] ABC-анализ товаров.
- [x] Прибыль и рентабельность.
- [x] КУДиР (УСН и патент), кассовая книга.

## Этап 7. Обмен и надёжность (ГОТОВО)
- [x] Повторный импорт из 1С без дублей + выгрузка обратно в 1С.
- [x] Загрузка прайсов и остатков из Excel/CSV.
- [x] Автоматические резервные копии базы (каждую ночь 03:30, хранение 14 дней).
- [x] Ручная выгрузка всех данных базы одним файлом.

## Этап 8. Надёжность учёта (по итогам аудита)
- [x] Долги считаются по направлению денег, возврат оплаты снова создаёт долг.
- [x] Прибыль по себестоимости, зафиксированной в момент продажи.
- [x] Отменённые документы не попадают в отчёты и КУДиР.
- [x] Возвраты приходят на склад по средней себестоимости партий.
- [x] Нельзя удалить товар с движениями; массовое удаление пропускает такие позиции.
- [ ] Сохранение документа одной транзакцией (шапка + позиции + проведение).
- [ ] Защита от дублей кода 1С: уникальный индекс по `ext_1c_id` в товарах и контрагентах.
- [x] Проверены 137 документов с «расхождением суммы» — это кассовые ордера (ПКО/РКО), у них нет строк товаров, суммы верны. Ошибки нет.

## Техническая часть
- База — свой PostgreSQL 16 на сервере 178.212.13.144 (Supabase и Firebase не используются).
- Остатки и себестоимость считаются в приложении (`src/lib/stock.ts`, `src/lib/posting.ts`, `src/lib/cost.server.ts`).
- Доступ к данным — свой вход (таблицы app_users/app_sessions), данные видны владельцу базы и приглашённым сотрудникам.
- Юрлица: `organizations` + `organization_id` в документах; нумерация, касса, печать и отчёты — по юрлицу документа.

## Порядок
Этапы 1–7 сделаны. Дальше — Этап 8: транзакционное сохранение документа, защита от дублей 1С, разбор расхождений сумм.
