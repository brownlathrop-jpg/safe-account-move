# Изоляция данных между клиентами: что подтвердилось и что делаем

Я перепроверил каждый пункт аудита по коду. Ниже — только то, что подтверждено чтением файлов.

## Подтверждено (реальные дыры)

1. **Перехват чужой записи.** При сохранении «по совпадению кода» (`upsert`) поиск существующей записи идёт по всей базе без ограничения клиентом, а затем запись переписывается вместе с её владельцем. Зная номер (ID) чужого документа или его код 1С, вошедший клиент может увести документ конкурента в свою базу.
2. **Чтение чужой записи по номеру.** Открытие одной записи по ID не проверяет, доступна ли она этому клиенту. Так читаются чужие товары, контрагенты, документы, склады.
3. **Записи «без базы» видны всем.** Сейчас любая строка без привязки к базе показывается всем клиентам и доступна им на запись.
4. **Связанные данные без проверки.** Подтягивание позиций документа и карточек-справочников тоже идёт без ограничения базой.
5. **Файл с настройками лежит в репозитории** и не исключён из него.

Про SQL-инъекцию автор аудита сам отозвал вывод — проверил, соглашаюсь: одинарные кавычки вырезаются, имена таблиц и полей идут через белый список и жёсткий шаблон. В истории репозитория секретов (пароль базы, ключ сессий, ключи почты/DaData) не найдено — в файле настроек только публичные значения. Возврат пароля и ответы входа проверены, там чисто.

## Что делаем (этап 1, сегодня)

1. Ограничить поиск при сохранении «по коду» только текущей базой и не давать менять владельца записи. Дополнительная страховка: изменение проходит лишь если запись принадлежит доступной клиенту базе.
2. Открытие записи по номеру — только внутри доступных баз, иначе «не найдено».
3. Записи без базы больше не общие: ввести явный короткий список настоящих общих справочников (единицы, банки, статусы), всё остальное — строго по базе. Запись «без базы» запрещена.
4. Подтягивание связанных данных — с той же проверкой базы.
5. Проверка имён полей отдельной функцией (вторая линия защиты) и обязательные скобки в условиях выборки.
6. Исключить файл настроек из репозитория, добавить пример настроек без значений, убрать адрес старой базы Supabase из скрипта переноса.

## Перед выкладкой — проверка рабочих данных

Сначала считаю на рабочей базе, сколько строк «висят без базы» по каждой таблице. От этого зависит список общих справочников: если у единиц/банков/статусов почти всё без базы — они в список; если без базы окажутся товары, контрагенты или документы — привязываю их к нужной базе до выкладки, иначе они пропадут из интерфейса. Также проверю, нет ли уже случившегося перехвата документов, и просмотрю журнал изменений на действия в чужих базах.

## После выкладки — проверка

Импорт из 1С прогоняю первым (он целиком построен на сохранении «по коду»), затем: список и карточка документа с позициями и контрагентом, создание документа и пересчёт суммы, склад (приход, движение, остатки), касса, КУДиР, кассовая книга. Плюс две проверки безопасности на копии базы: чтение чужого документа по номеру и попытка перехвата — должны возвращать «нет доступа».

- `src/lib/pg.server.ts`: `GLOBAL_TABLES`, `assertField`, `fieldExpr`, `applyWhere` (скобки + ветка глобальных таблиц), `assertWrite` (запрет NULL-workspace), ветка `upsert` (conflict-фильтр + `workspace_id = any($5)` в `update`), `getRowById(table, id, scope)`, `fetchByIds`/`fetchByFk`/`hydrate` с параметром `scope`.
- `src/lib/db.functions.ts`: `dbGetById` получает `scope` из `accessibleWorkspaces(user.id)`.
